# 自主陪伴管理卡片（T1u）

2026-11-02；基于 T1 冻结的自主陪伴接口，补齐用户可见操作入口。后端闭环见 [T1 实施记录](2026-11-02-autonomous-companion.md)。本单元只改前端、对应模拟测试和本 case，不改变后端、主人绑定、实际配置或已有 QQ/桌宠运行。

## 现象、链路与机制

T1 有默认关闭的状态、配置、公开预览、运行和停止 API，但设置页没有入口。新增 `client.js` 的 `CompanionCard`，放在 DSH「设置 → SurfCore → B站」账号卡后，常驻可见；不藏在高级设置中。只调用 `/dsh-surfcore/api/companion/{status,config,preview,run,stop}`，继续使用已有 DSH 会话及 Host/Origin 鉴权。

首屏只读 GET status，显示已开启/关闭、运行/空闲、下次浏览、最近来源和 sent/failed/unknown 结果；unknown 和遗留 pending 明确提示待核对、不会补发。默认值从服务器取得，不在组件挂载时写配置。关闭自动记忆写入时显示未宣称已保存材料/想法。

表单调整浏览间隔、每天最多主动尝试、联系冷却。勾选后仍须点击「保存并启用（仅主人私聊）」才 POST config；卡片明确说明只联系已绑定主人。后台每 10 秒读取状态，保留尚未保存的表单；响应版本比较阻止迟到的旧 status 把已停止状态翻回开启。刷新和保存均不改统一注意力里的安静时段、专注或预算。

「只读预览材料」POST 空对象到 preview，不调模型、不发送；展示标题、作者、简介与服务端标注的真实材料范围。只有实际取得官方字幕时显示只读字幕节选，否则明确“仅标题/作者/简介，不代表看过完整视频”。来源链接只用合法完整 BV 重建为固定 HTTPS 官方域，忽略响应中的任意 URL；新窗使用 noopener/noreferrer。

「立即运行（可能发给主人）」明确说明它可能导致真实私聊，但仍由后端核对所有限制。运行时禁用重复运行和参数写入，保留「停止并关闭」。停止 POST 空对象到 stop，关闭并请求取消在途轮次；已提交平台的消息无法撤回，以上次结果为准，不自动补发。未启用或非 local 后端时，运行不可点；预览也要求 local。卡片提供现有本地能力管理入口，说明统一注意力的主动开关还需开启，且安静、专注、冷却、预算及白名单始终生效。

失败在当前卡片显示 code/error/hint，后台正常轮询不会吞掉刚发生的操作错误；用户可刷新重试。状态/配置/停止请求限 15 秒，公开预览 75 秒，完整轮次请求 240 秒；超时明确标为结果未确认，要求先刷新核对，不重复点击补发。超时只结束页面等待，不擅自推断服务端已经停止。

## 影响与取舍

影响一个宿主设置页组件及其测试导出；界面没有 B站评论、动态、私信、群聊或陌生人发送动作，没有凭据输入或回显。界面启用属于明确的本机配置操作，但本次实现与测试没有操作真实配置或发送真实消息。

路线 A 只给用户复制 API 命令，代码少，但用户看不到运行/未知结果，容易重复运行或误解关闭范围。路线 B 在既有 B站 页增加一张卡片，复用组件/样式和已冻结 API，成本小，能直接呈现风险与停止状态；选择 B，不新增导航框架或第二套管理后台。
