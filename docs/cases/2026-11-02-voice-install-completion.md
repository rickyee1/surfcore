# 语音包传输完成不能冒充安装完成

## 现象与范围

2026-11-02，B站隔离验证时审计为 107/108；唯一失败是 `test-voice-cloud-credentials.mjs` 的“装完的配置里没有任何预置凭据”断言。同一测试普通隔离运行可通过，但暂停合成配置的复制回调即可稳定复现，不是共享临时目录污染。

本修复仅涉及语音包安装进度，不新增语音功能，不启动真实服务，不访问真实凭据，不请求外网，不改版本。运行环境为 Windows、Node.js 24；部署中的 DSH、QQ、桌宠未因这次修复被停止。

## 根因与完整逻辑

1. **链路**：`src/bridge.js` 创建并缓存 `createVoicePacks`；安装接口启动异步任务，调用方通过列表接口轮询 `install.phase`。`src/voice-packs.js` 的传输回调直接更新该字段，测试使用同一公开状态等待完成。
2. **机制**：本地目录复制和本地压缩包解压结束时，`fetchToLocal` 原来立即报告 100%“完成”。这时还没执行 `ensurePackConfig` 的凭据清洗、后置步骤和安装状态持久化。配置复制后短暂可见，等待者于是提前读到合成模板，甚至可能在清洗失败前看见成功状态。
3. **影响面**：同一语音安装进程及其状态读者，包括管理界面与测试。问题会误报安装成功或造成检查偶发失败；本次只用一次性夹具复现，不涉及用户语音费用或真实密钥内容。正常重装保留用户配置的规则不变。
4. **取舍**：只在测试里重试读取直到内容符合预期，改动少，但掩盖产品完成状态错误。选择修改两处传输通知，并让测试主动暂停清洗前的时序窗口；成本低，直接修正状态契约，回滚范围明确。
5. **生效**：只在加载新版 `src/voice-packs.js` 的宿主进程生效。部署时由主会话在合适窗口重新加载相关桥接/插件宿主；不需要重启已有语音引擎，不在安装进行中重启宿主。
6. **验证**：旧实现上新增的暂停复制与清洗失败断言确定性失败；修复后通过。检查真实状态，不通过延长等待或读取重试来掩盖错误。
7. **回滚与限制**：回滚本 case 对应的两个传输进度修改和新增测试代码即可恢复旧行为，但也会恢复早报完成的竞态。合成测试没有验证真实语音包下载、模型加载和计费服务；这些不在本修复范围。

## 修法与失败行为

本地复制后报告 99%“复制完成”，本地解压后报告 99%“解压完成”。只有 `install()` 原有的最终成功分支，在清洗、必需后置步骤和安装登记之后报告 100%“完成”。异常继续进入原有“失败”分支并保留安装错误，调用方应展示错误并修复环境后重试。

隔离回归在合成配置已经落盘、清洗尚未开始时暂停复制完成回调，断言安装保持非终态；另一个独立夹具拒绝配置清洗写入，断言进入失败态且没有成功登记。所有替身只匹配各自临时目录中的文件，并在 `finally` 恢复；既有新装清凭据、重装保留用户配置检查仍运行。
