# 路遥本地能力融合

日期：2026-11-02。基线 `59ec3066f7d42a0452fae01f170c9a8484d5dbe5`，版本保留 `0.8.6`。用户要求 fork 并实现融合方案，在独立目录部署测试。

## 现象与机制

旧共享记忆卡不能表达每个私聊/群的受众范围；最终提示词里的保密要求不能阻止旧卡片、DSH 历史、派生摘要和待发消息绕过纠错与删除。

插件监管单个 Python SQLCipher 进程，可信适配层创建绑定，检索前过滤受众。投影带角色/记忆代次，实际发送前复核。纠正失效旧派生认知；删除沿来源副本和派生关系清理，保留防重放摘要。主动预算和未知送达结果共用持久账本。

## 完整逻辑

- 链路：DSH 插件/管理宿主 → JS facade/supervisor → 私有 stdio → SQLCipher；QQ 通过认证宿主转发。队列输出验证原始上下文，不能给旧回复补新授权。
- 影响面：插件、桥接、能力进程三个进程角色，管理/桌宠/QQ/B站四类读者。按上游粗略口径 3×4×1=12，数据隔离需独立行为验收。默认不开启，不读原路遥数据库，不增加后台模型循环。
- 取舍：全 JS 重写需重验加密治理，两个聊天核心会重复回复；选择 Python 能力进程并保留 SurfCore 编排。
- 生效：重启 DSH profile 与桥接；独立管理服务器重启刷新 HTML。测试服务器和 DSH 插件使用不同数据根。
- 失败可见：新增错误包含 code/error/hint；密钥、旧代次、版本冲突和服务故障均给明确下一步。
- 回滚：正式写入后只能暂停，导出核对后明确回迁；保留数据库和 DPAPI 文件。
