# SurfCore × 路遥完整融合执行与验收

更新：2026-11-03，Asia/Shanghai。状态：实施中，已有实测失败，不是完成报告。实际部署为9f456d2，当前结果见[实测case](cases/2026-11-03-full-integration-live-results.md)。

用户在现有 QQ、桌宠与 B站只读部署后要求“把所有功能全部实现”，特别指出“自己翻 B站，然后把想到、想说的话主动发给我”。本执行单扩展至原融合方案 M0–M5，保留 SurfCore 为唯一对话编排。既有基线 `e9d33b481025b73e8398b0d76548413ab35b3aa8` 已推送用户 fork；源方案是原工作区 `docs/SURFCORE_LUYAO_INTEGRATION_PLAN.md`。原路遥目录只作参考，现有配置、记忆、账号和资产保留。

## 交付边界

- 已明确的主动联系目标是已绑定主人 QQ 私聊；不得扩为群聊、陌生人或任意账号。
- 实现现有平台动作的权限与预览控制；B站公开评论、动态和私信的实际外发仍须落到具体目标与内容范围，不能把“全部实现”当成任意发布许可。
- 本机工具、麦克风和屏幕能力提供本机可见授权、撤销和紧停；实际设备采集由用户在完成的界面触发。未取得设备证据的项不得标为通过。
- 原方案明确列为独立扩展的 Live2D、完整持续感知、签名安装器不自动加入本次。版本号、tag、Release 不变；代码可保存到用户已授权的 fork 分支。
- 不以开关打开、接口存在、mock 或审计全绿代替真实模型、平台、设备与恢复证据。

## 架构与取舍

采用现有 DSH 宿主和单一 Python 能力服务；纯 `purpose-engine` 继续选择目的。`local` 模式新增受治理的自主陪伴适配，替代未纳管的旧自主调度，不并行运行两套聊天／人格／预算。已有 `context/attention` 协议保持兼容。

直接放开旧 B站 agent 与 reserved2 的路线代码少，但会重引完整 CLI 工具、私有日记、未绑定代次的外发及已发现的长回合问题。选择固定公开读取、有限内容理解、无工具模型生成、单次可信投递；发送前重核原始上下文、主人身份、额度和白名单。旧路径继续受守卫约束，直到逐项完成纳管。

后端按兼容扩展增加记忆提案事务、工具 Broker、加密快照／恢复；不把外部副作用包装成可回滚数据库事务。恢复优先合并独立最新删除记录，授权、密钥和设备许可不随旧快照复活。

## 实施与验收纪律

本批分级 L3，高风险。主会话负责协议、集成、部署与用户交接；执行者复用已验证的 Sol high 路由，独立关键验收复用 Astra high 会话；实际 provider 和费用未由宿主提供，记为未知。默认每任务至多三次有新证据的实现尝试，不跨会话清零。用户仅追加的T1第4次也已失败；semantic-host第3次失败。取消后续自动修补上限的问题待用户回答，未答不重试；独立新功能P1不清零这些计数。

单一写入所有权：T1 独占自主陪伴 JS 及声明的桥接/宿主接线区域；T2a 独占 Python 服务及相关服务测试。前端与共享文档由主会话协调，禁止并行覆盖。后端兼容接口冻结后才接新调用方。

源码基线归档位于 `.local/backups/full-integration-baseline-e9d33b4/source.zip`。测试只用隔离夹具；真实配置、模型、设备与平台操作由主会话执行。每批有 case 七步逻辑、完整差异、回滚与交接；最终需要当前版本的 audit、对应插件/协议回归、独立验收及适用实测。

进度保存在忽略提交的 `.local/evidence/full-integration/state.json`。本文件只记录最小计划与可核查状态，不能作为通过证据。只有软件、实际模型/平台、适用设备与运行观察全部达到要求，才可称本次完整验收通过。
