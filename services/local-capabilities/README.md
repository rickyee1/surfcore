# Local capability service

Python 3.13 and SQLCipher only. Install `requirements.txt` in the repository's isolated `.venv`.

```
.venv\Scripts\python.exe services/local-capabilities/server.py --data-dir .local/local-capabilities
node scripts/test-local-capabilities-service.mjs
```

The parent owns stdin and lifecycle. EOF closes the encrypted connection and releases the OS lock; no background model calls or scheduling threads exist. One bounded JSONL request (maximum 1 MiB) has one transaction. Failures return `ok:false`, `code`, `error`, `hint`; database failures never open legacy memory or plaintext SQLite. Startup failures remain observable through the same protocol until stdin closes.

The v1 wire contract is in [PROTOCOL.md](PROTOCOL.md). `storage.py` owns SQLCipher, fresh 32-byte key provisioning protected by current-user Windows DPAPI, and the directory lock. An existing database without its protected key refuses startup. `SURFCORE_LOCAL_KEY` is an explicit 64-hex override for isolated tests/local configuration, never an inferred default. Keys do not appear in exports or protocol responses. A broken encrypted database is preserved, rather than replaced. SQLCipher protects this service's managed files; upstream DSH/platform logs are outside its protection.

`core.py` owns opaque random runtime bindings and epochs, persisted memory versions, audience filtering, revisions and attention accounting. The trusted parent must keep activation, binding and management operations away from model tools. It supplies resolved platform/account/conversation/principal identity; this process does not independently authenticate QQ accounts. A local management binding requires platform `local`, scope `owner:local`, `is_owner:true`, `management:true`. Pet and QQ scopes remain isolated even when `is_owner:true`. After explicit local administration, the trusted adapter may bind platform `pet` or QQ private owner to `owner:local` with `is_owner:true`, `management:false` for cross-channel sharing; QQ principal must equal conversation. This mapping grants no management rights. QQ private principal must match conversation; normal query sees only its bound audience plus `bili:public`. Quarantine is readable only through the management path. Derivations require every recursive source to remain active and visible. Queries cap results at 100.

Ingest records an episode, not a model-verified assertion. `memory.propose` supports add only with the same event fields as ingest; it cannot replace a user revision. Correcting a source recursively suspends its existing derived descendants and advances their revisions, preserving their management history while excluding stale projections from answers. Source refs and original/current content fingerprints survive deletion as SHA-256 tombstones without text. Delete removes revision bodies and recursively removes derived records and existing copies linked by shared source, event or exact-content fingerprints. This provenance closure spans the current character's audiences and never crosses characters. Retrying a deletion is idempotent. Tombstones reject event, source or exact-content replay even across audience scopes after restart. This does not attempt to detect arbitrary paraphrases. Encrypted snapshot recovery now applies the independent latest deletion authority as described below; older backup copies are not claimed to be physically erased.

Migration is a single atomic transaction of up to 500 records; same migration ID with changed content conflicts. Each record remains in `quarantine`, marked `legacy_summary`, with supplied references only. Suspended/invalidated records never become active through migration, and deleted records immediately become tombstones. Export/detail are explicit management operations and return plaintext to the parent only when requested.

Attention configuration is persisted per character and shared by all that character's channels. Default is disabled. Supported timezones are `Asia/Shanghai` and `UTC`; quiet hours support midnight crossing (`start == end` means all day). Reservations count toward daily quota/cooldown; identical outreach IDs cannot be reused. Finalization is tied to the original binding and epoch. Explicit `failed` releases budget but retains the ID to prevent accidental retry. `unknown`, retirement, and abandoned reservations after restart consume budget. Every sent/unknown event increases unanswered count; after three, intensity halves to a minimum of 0.25, tightening daily quota and cooldown. Only a bound owner pet/private input resets unanswered count and restores intensity by 0.25. Final checks re-evaluate quiet/muted/focused state and can include `memory_epoch`; the parent must additionally call `context.validate` immediately before sending. This is conservative local accounting, not a guarantee of external exactly-once delivery.

Restart requires fresh activation/bindings. Activating a role again or retiring it revokes its old bindings and unresolved reservations. The host must retire the previous role when switching. Disable/pause the new backend after writes; automatic legacy rollback would lose sovereignty updates. Revert code only after preserving `.local/` and accounting for those writes.

Conversation memory queries prioritize user-pinned corrections, then newest insertion (`rowid DESC`), before the bounded result limit. This deterministic priority retains authoritative corrections and recent episodes; it is not semantic search. Exact pending-input validation uses `context.sources` rather than assuming a bounded memory query contains every pending message. The bound request takes `{source_event_ids:[...]}` with at most 20 unique nonempty event IDs (maximum 500 characters each). It returns `{sources:[{source_event_id,status,text?,revision?}],memory_epoch}` in input order. Lookup is restricted to the binding's exact character and audience, including for management bindings; other audiences and public records outside that audience return `missing`. Active records return their current corrected body and revision. Suspended/invalidated records return `suspended` without body; deleted records retain scoped event digests and return `deleted` without body after restart. No global tombstone lookup discloses another audience's deletion status. `missing` can represent actual live input never persisted while auto-write was off, but only the trusted adapter may use its own such live input; stored or historical content must never be revived from a `missing` response. `context.validate` remains mandatory immediately before sending.

Before returning an active body, `context.sources` applies the same recursive source-visibility gate as a normal memory query. Its dependency set is restricted to the binding's normal audience even when the binding has management rights. If any ancestor is inactive or outside that audience, the derived event returns `missing` without body or revision, matching an absent event and concealing the hidden ancestor's state. Direct same-audience suspended/deleted records retain their body-free status responses.

The T2a service extension adds source-revision-bound writer batches, atomic assertion/relationship-projection commits, management review/resume, and a rebuildable keyword index. The old `memory.propose` add-only episode semantics remain unchanged. No model calls or semantic vectors run in Python. Pending episodes are restricted to the exact bound channel; proposal history is a management-only view. Detailed request payloads and integration gaps are in [T2A_API.md](T2A_API.md).

Password-encrypted logical snapshots now support isolated staging and transactional restore. Independent `sovereignty.db` retains append-only deletion fingerprints and local snapshot identities; it is never replaced by restore. Current deletion history is merged before any restored record becomes usable. An unknown/missing latest source ledger defaults to a recovery pause, with explicit management review required. Backups contain neither the source SQLCipher key/DPAPI file nor runtime identities, grants, attention policy or pending writer tasks. They cover this service's memory domain, not full persona/assets, platform history, or OS credentials. Older encrypted snapshot/staging artifacts are retained; deletion prevents their automatic reuse rather than promising physical erasure of all old copies.

Tests use temporary synthetic stores, including actual Windows DPAPI, no platform credentials or user memory. The service launcher runs original compatibility checks and T2a backend counterexamples. Original repository audit/regressions and real channel/model acceptance are owned by integration. See `provenance.json` for adaptation inputs and dependency boundary.
